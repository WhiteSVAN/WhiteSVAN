# TrustSVAN — Architecture, Data Model & Design Spec

> Verified performance network for quants / systematic & algo traders / prop‑firm
> operators. Traders import broker or prop‑firm history, get a **proof‑backed**
> performance profile, publish research, and get discovered by clients and
> allocators. It is a **pure SaaS reporting tool** — it does not manage money,
> execute or copy trades, send signals, give allocation advice, or take fees.

This document is the single reference for the stack, the database design, the
component/architecture layout, and the UI/UX system. It reflects the code as
built (rapid‑prototype phase).

## 2. Architecture — the one rule

**Code calculates numbers. AI only explains them.** The flow is strictly
one‑directional; the model never computes P&L, returns, or drawdown.

```
CSV / manual entry
  → parse + alias auto-map            (src/lib/csv)
  → Trade rows                        (raw CSV kept in Trade.raw)
  → daily rollup                      (DailyPnl, rebuilt on import)
  → metrics engine                    (src/lib/metrics.ts — pure, source of truth)
  → trust engine                      (src/lib/trust.ts — scores, severity, verdict)
  → diligence engine                  (src/lib/diligence.ts — allocator brief)
  → AI layer                          (src/lib/ai — writes report sections from text metrics)
  → review / publish                  (immutable ProfileVersion snapshot)
  → public operator card              (/p/[slug])  + diligence view (/p/[slug]/diligence)
```

### Layered modules (`src/lib`)

| Module                      | Responsibility                                                                   |
| --------------------------- | -------------------------------------------------------------------------------- |
| `metrics.ts`                | Pure, dependency‑free metrics (P&L, win rate, profit factor, drawdown, equity).  |
| `trust.ts`                  | Operator trust layer: 6 sub‑scores + weighted **Transparency Score**, drawdown severity, big‑win dependency, bounce‑back, plain‑English verdict, **Proof Levels 1–5**. |
| `diligence.ts`              | PE‑style allocator brief (strengths / risks / what‑to‑monitor / data quality) — guardrail‑safe, past performance only. |
| `proof.ts`                  | Derives a `TradingAccount`'s Proof Level from evidence (CSV→L2, statement→L3, tax return→L4). |
| `csv/parse.ts`,`brokers.ts`,`fifo.ts` | PapaParse + alias auto‑detection (IBKR Flex/Activity, Fidelity/E\*TRADE realized G/L, manual template) and a FIFO round‑trip matcher. |
| `ingest/import.ts`          | Import orchestration: hash, dedupe, write trades, rebuild `DailyPnl`, `ImportBatch`. |
| `ai/*`                      | Provider‑agnostic report generator; strict system **prompt** + **compliance** banned‑language filter + zod report **schema**. |
| `freshness.ts`,`risk-events.ts`,`published-profile.ts`,`version.ts` | MVP2 "living profile": freshness windows, dated risk events, immutable published snapshots. |
| `redaction.ts`,`public-copy.ts` | `$`/broker redaction for the public card; compliance checks on user copy. |
| `auth/dal.ts`,`auth/schemas.ts`,`auth/reset.ts` | Auth data‑access layer (the authorization boundary), zod schemas, password‑reset tokens. |
| `db.ts`,`logger.ts`,`email.ts`,`hash.ts`,`rate-limit.ts`,`format.ts`,`request.ts` | Prisma singleton, structured logging, email shim, hashing, rate limiting, formatting, request helpers. |

`metrics` JSON is persisted verbatim on `Report.metrics` and `ProfileVersion.metrics`
so a published report is **reproducible** even if trades change later. AI output
lives separately on `Report.aiReport`.

## 3. Database design

PostgreSQL 16 via Prisma. **Money is `Decimal(18,2)`, prices `Decimal(18,6)`,
quantity `Decimal(18,4)`; calendar‑only dates use `@db.Date`.** IDs are `cuid()`.
All domain rows **cascade‑delete** from their owner. 8 migrations to date.

### 3.1 Auth.js group

| Model               | Purpose & key fields                                                                 |
| ------------------- | ------------------------------------------------------------------------------------ |
| `User`              | Account identity. `email` (unique), `passwordHash` (bcrypt, credentials sign‑in), `name`, `image`. Owns profile, trading accounts, reports, evidence. |
| `Account`           | OAuth/credentials **provider link** (Auth.js). ⚠️ Not a brokerage account. `@@unique([provider, providerAccountId])`. |
| `Session`           | DB session row (unused with JWT strategy but kept for adapter shape).                 |
| `VerificationToken` | `identifier` + unique `token` + `expires`. **Reused for password‑reset tokens.**      |

> ⚠️ A user's **brokerage** account is `TradingAccount`, never `Account`.

### 3.2 Domain group

| Model               | Purpose | Notable fields | Relations / constraints |
| ------------------- | ------- | -------------- | ----------------------- |
| **`TraderProfile`** | Public operator‑card identity (`/p/[slug]`). | `slug` (unique), `displayName`, `bio`, `strategy`, `instruments`, `riskRules`; privacy: `isPublic`, `hideAmounts`, `hideBrokers`, `disclaimer`; client‑attraction: `openToWork`, `headline`, `services`, `contactUrl`; living‑profile: `updateCadence` (enum), `lastPublishedAt`. | 1‑1 `User`; has `versions`, `riskEvents`, `followers`, `notifications`. |
| **`TradingAccount`**| A brokerage/prop account. | `broker`, `accountName`, `startingBalance Decimal(18,2)`. | belongs to `User`; has `trades`, `dailyPnl`, `reports`, `evidence`, `importBatches`. `@@index([userId])`. |
| **`Trade`**         | Raw imported row. | `tradeDate @db.Date`, `symbol`, `assetType`, `side`, `quantity(18,4)`, `entry/exitPrice(18,6)`, `realizedPnl(18,2)`, `fees(18,2)`, **`raw Json`** (original row). | belongs to `TradingAccount`. `@@index([accountId, tradeDate])`. |
| **`DailyPnl`**      | Per‑account/day rollup, rebuilt from trades on import. | `tradeDate @db.Date`, `grossPnl`, `fees`, `netPnl`, `tradeCount`, `notes`. | **`@@unique([accountId, tradeDate])`**. |
| **`ImportBatch`**   | Audit trail — one row per import. | `source` (enum), `broker`, `originalFilename`, **`fileHash`** (sha‑256, idempotency), `rowCount`, `periodStart/End @db.Date`, `netPnl`. | belongs to `TradingAccount`; has `versions`. **`@@unique([accountId, fileHash])`**. |
| **`ProfileVersion`**| **Immutable** snapshot at a publish moment ("living profile" history). | `versionNumber`, `period`, **`metrics Json`** (code‑of‑record), `netPnl`, `returnPct`, `transparencyScore`, `proofLevel`, `freshnessStatus`, `changeSummary`, `sourceBatchId`. | belongs to `TraderProfile`; optional `sourceBatch`; has `riskEvents`. **`@@unique([profileId, versionNumber])`**. |
| **`Report`**        | Generated brief. | `period`, **`metrics Json`** (code‑of‑record), **`aiReport Json`** (AI sections), `status` (DRAFT/APPROVED/PUBLISHED). | belongs to `User` + `TradingAccount`. |
| **`Evidence`**      | Proof locker file. | `kind` (enum), `label`, `originalName`, `mime`, `size`, `isPublic`. A `STATEMENT`→L3, `TAX_RETURN`→L4. | belongs to `User`, optional `TradingAccount` (SetNull). Files stored under `storage/` (git‑ignored), served at `/api/evidence/[id]`. |
| **`RiskEvent`**     | Dated, plain‑English risk flag created on publish. | `type` (enum), `severity` (enum), `eventDate`, `title`, `description`, `metricBefore/After`, `isClientVisible`. | belongs to `TraderProfile`, optional `ProfileVersion`. |
| **`ProfileFollower`**| Client watchlist subscription (email). | `email`, `status` (enum), `frequency` (enum), `verifiedAt`. | belongs to `TraderProfile`; has `notifications`. **`@@unique([profileId, email])`**. |
| **`NotificationEvent`**| Outbound notification queue (delivery deferred). | `type` (enum), `subject`, `body`, `status` (QUEUED/SENT/FAILED), `sentAt`. | belongs to `TraderProfile`, optional `ProfileFollower`. |
| **`WaitlistEntry`** | Landing‑page beta capture. | `email` (unique), `note`. | — |

### 3.3 Enums

`UpdateCadence` (DAILY/WEEKLY/MONTHLY/MANUAL) · `ImportSource` (CSV/MANUAL/STATEMENT/BROKER_API) ·
`ReportStatus` (DRAFT/APPROVED/PUBLISHED) · `EvidenceKind` (STATEMENT/TAX_RETURN/PAYOUT/EXPORT/OTHER) ·
`RiskEventType` (DRAWDOWN/WORST_DAY/BIG_WIN_DEPENDENCY/LOSS_VS_WIN/STALE_PROFILE/SCORE_CHANGE/RECOVERY) ·
`RiskSeverity` (INFO/WARNING/CRITICAL) · `FollowerStatus` (PENDING/ACTIVE/UNSUBSCRIBED) ·
`FollowFrequency` (WEEKLY/MONTHLY/RISK_CHANGES_ONLY) · `NotificationType` (WEEKLY_UPDATE/MONTHLY_REPORT/RISK_CHANGE/STALE_PROFILE) ·
`NotificationStatus` (QUEUED/SENT/FAILED).

### 3.4 Entity relationships (text ERD)

```
User 1─1 TraderProfile 1─* ProfileVersion *─1 ImportBatch
 │            │  1─* RiskEvent  *─0..1 ProfileVersion
 │            │  1─* ProfileFollower 1─* NotificationEvent
 │            └─ 1─* NotificationEvent
 ├─1─* TradingAccount 1─* Trade
 │            ├─1─* DailyPnl   (unique account+day)
 │            ├─1─* ImportBatch (unique account+fileHash)
 │            ├─1─* Report
 │            └─0..* Evidence (SetNull)
 ├─1─* Report
 └─1─* Evidence
```

## 5. UI/UX specification

### 5.1 Design language

A **black, institutional “night terminal”** aesthetic — calm, data‑forward,
high‑contrast, minimal chrome, with graphite surfaces and metallic white accents.
Two‑sided positioning: verified traders ↔ allocators. Copy is structured
(thesis/evidence/risk), never hype.

### 5.2 Color tokens (`globals.css`)

| Token                 | Value      | Use                                  |
| --------------------- | ---------- | ------------------------------------ |
| `--background`        | `#030303`  | Page background (near black)         |
| `--foreground`        | `#f4f4f5`  | Body text                            |
| Surface / card        | `#080808`  | Panels (`bg-white` remapped)         |
| Border                | `#27272a`  | Hairline borders / dividers          |
| **Accent (steel)**    | `#e4e4e7`  | Brand, links, CTAs, focus, selection |
| CTA hover / solid     | `#ffffff` / `#e4e4e7` | Primary buttons           |
| Secondary accent      | `#71717a`  | Smoky ambient glow                   |
| Muted text            | `#a1a1aa` → `#71717a` | Secondary / tertiary text |
| Semantic — good       | `#e4e4e7`  | Positive P&L, verified, open‑to‑work |
| Semantic — warn       | `#a1a1aa`  | Elevated/high risk                   |
| Semantic — bad        | `#71717a`  | Losses, severe risk                  |

Page has a fixed radial‑gradient ambient backdrop with subtle white and graphite
halos plus a linear black gradient. Selection is steel‑tinted.

> **Dark‑theme shim:** much of the MVP was authored with light Tailwind classes
> (`bg-white`, `text-slate-900`, …). `globals.css` remaps those utility **classes**
> to dark values with `!important`. **Caveat:** this only covers classes — inline
> `style` values and Recharts/3rd‑party props bypass it, so chart colors and any
> inline backgrounds are set explicitly to dark values (lesson learned: white leaks).

### 5.3 Typography

- **Apple system stack** (`-apple-system`, `SF Pro Display`, `SF Pro Text`,
  `Helvetica Neue`) for UI; **SF Mono** stack for numbers/codes.
- A restrained `New York` / Baskerville-style serif accent is reserved for the
  `Trust` portion of the wordmark, nodding to LoveFrom's serif identity without
  importing or copying proprietary type.
- Headings: `font-semibold`, no artificial tracking, hero up to `text-5xl/6xl`.
- Numbers use `tabular-nums` for alignment in stats/leaderboards.
- Brand wordmark: serif `Trust` + swan-as-`S` + sans `VAN`, in metallic monochrome.

### 5.4 Component patterns

- **Card:** `rounded-lg border border-slate-800 bg-slate-900/70 p-5`.
- **Badge / pill:** monochrome steel/graphite treatment, using border opacity, fill opacity, and text weight rather than hue.
- **Primary button:** steel fill, `text-slate-950`, hover white. **Secondary:** slate border, steel hover.
- **Inputs:** shared in `components/form.tsx`; `color-scheme: dark`; errors and success states use neutral banners.
- **Charts:** 240px tall, gridlines `#27272a`, axis ticks `#a1a1aa`, steel/charcoal series, dark tooltip (`#080808` bg, `#27272a` border).
- **Leaderboard card** (`/explore`): rank chip, name, “Open to work”, “Verified · Proof L_n_” badge, Growth/Drop/Trust mini‑stats, severity chip.
- **Layout widths:** `max-w-6xl` (marketing), `max-w-5xl` (directory), `max-w-4xl` (profile), `max-w-3xl` (settings). Generous vertical rhythm (`space-y-8/10`).

### 5.5 Interaction & accessibility

- Hover lifts borders to steel; dropdowns close on outside‑click / Escape; `aria-haspopup`/`aria-expanded` on menus, `role="status|alert"` on banners, `aria-hidden` on decorative icons.
- Responsive grids (`sm:`/`md:`/`lg:` columns); mobile‑first.
- **Print:** `print:hidden` chrome and a white print background for Save‑as‑PDF of profiles/reports.

### 5.6 Key UX flows

1. **Get verified:** signup → onboarding → upload CSV → preview → import → dashboard → publish → public card. Proof Level rises with statement (L3) / tax return (L4).
2. **Get discovered/hired:** set `openToWork` + `headline` + `services` + `contactUrl` in settings → “Work with me” CTA + Open‑to‑work badges on card and directory.
3. **Allocator diligence (PE combine):** `/explore` leaderboard → profile → `/p/[slug]/diligence` brief (strengths / risks / monitor) → contact.

## 6. Guardrails (load‑bearing, not boilerplate)

The product reports on **past** performance only. It must never tell anyone what
to trade, how much to allocate, or whether to invest:

- The AI report generator runs a strict system prompt and returns JSON matching a
  fixed schema; a **banned‑language filter** rejects *guaranteed returns, risk‑free,
  safe investment, you should invest, allocate X percent, copy my trade, will make
  money, assured profits*.
- The **diligence engine** is descriptive only — it grades the *record*, never
  recommends allocating; a unit test asserts the output contains no allocation/
  “you should invest”/“copy” language.
- Every public card and brief carries a “past performance does not guarantee
  future results” disclaimer.
- **Out of scope (v1):** broker OAuth/auto‑execution/copy‑trading, signals,
  personalized advice, AUM/performance fees, custody, full RIA/CTA workflow.
